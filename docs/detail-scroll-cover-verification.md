# 详情页回弹与录音封面验证

## 已取得的证据

2026-09-08 直接读取微信开发者工具模拟器第一条记录：

- 录音时间为 11:41，首图 key 为 `photos/2026-09-08-114110/0-k11l43.jpg`。
- `coverPhotoIsBook: false`、`coverPhotoLoaded: true`：显示的是文章首图回退，不是专用 `cover.jpg`。
- 首图的公开原图接口实测返回 200（image/jpeg）；同目录专用 `cover.jpg` 在两个域名均返回 404。
- 模拟器标题含“iOS 版”，先前手机截图标题没有这一更新，表明两侧文章元数据存在差异。

代码与回归测试确认：`enrichArticleMeta` 将空首图 key 也视为完整缓存；下拉刷新此前未强制重读文章，导致先缓存无图、后添加首图时仍不显示首图。已修正手动刷新链路，重新读取标题和首图；排队中的用户刷新也保留强制刷新要求。

手机调试连接在现场读取前已断开，尚未直接读取该手机的缓存内容，也尚未真机确认修复后的显示结果。iOS 的当前缓存未读取。不能把模拟器首图可见解释为专用封面存在。

## 实现

- `pages/detail`、`pages/community-detail`：内容层 `min-height: calc(100% + 1px)`，显式开启回弹；短内容保留滚动空间。
- `pages/recordings`：手动刷新强制更新文章元数据；封面下载失败不再永久跳过，已显示的首图可以升级为专用封面。取消已下载本地封面的懒加载。
- `services/library.js`：支持强制更新文章元数据；照片下载增加原生 timeout 与独立定时兜底（缩略图 8 秒、原图 15 秒），忽略超时任务迟到的回调并释放在途缓存。
- 已移除临时 `[DEBUG-record-cover]` 日志；现有下载日志保留。

## 验证

运行 `npm test`、`npm run validate:miniapp`。回归覆盖先无图后加图、排队中的强制刷新、下载超时回退、超时后刷新重试、迟到回调隔离，以及详情页滚动配置。

真机需重新编译扫码，下拉刷新“我的录音”，检查 11:41 第一篇标题和首图是否更新。无需先清缓存。若仍无首图，应检查真实首图路径 `0-k11l43.jpg` 的下载响应，而不是仅看 `cover.jpg` 的 404。

在 iPhone 微信分别打开两种短详情页，上下拖动确认回弹；长文检查能读到末尾、固定工具栏正常。Android 微信检查滚动可用，不保证呈现相同回弹动画。

## 跨端与代价

未修改其他仓库、API、图片 marker 或路径契约。Android 和 iOS 的专用封面失败缓存也有同类潜在风险，建议另行检查；HarmonyOS 应验证首图失败后的恢复。此次小程序改动无需其他端同步协议。

手动刷新将增加文章元数据读取（沿用最多 5 个并发）；普通加载仍复用缓存。仍不存在的专用封面会在后续刷新时重试。慢网络超过照片下载时限可能需要再次重试。
